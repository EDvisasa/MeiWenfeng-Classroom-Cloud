Architecture Review: Deepening Opportunities

Based on the domain model (CONTEXT.md) and current codebase, here are the architectural friction points identified along with proposals for deepening the modules.

1. Decouple LLM Stream Parsing from Tool Execution

LLM-Prompt-Injection Candidate
Strong

Files: backend/services/agent_tools.py (AgentExecutor)

Problem

The AgentExecutor.run is a shallow module acting as a god-function. It mixes LLM stream chunk parsing (extracting OpenAI format tool_calls), threading for tool execution, and state management. This lacks locality because adding a new provider or changing stream parsing breaks the tool execution logic. The seam is non-existent.

Solution & Benefits

Extract a StreamParser adapter that yields generic events, and a separate ToolExecutionEngine.

Benefits: High leverage. We can test the stream parser independently from the tools. The tools engine becomes a deep module providing a clean interface for executing an array of tool calls.

2. Extract Persona Prompts from Router

LLM-Prompt-Injection Candidate
Worth exploring

Files: backend/services/model_router.py (stream_chat)

Problem

stream_chat physically mutates the conversation history by hardcoding a 30-line perfect_one_shot string. This leaks persona logic into the network router module. The router module shouldn't know about Mei Wenfeng or the 6-step think process.

Solution & Benefits

Move the one-shot injection into a PromptBuilder adapter in prompts.py. The router's interface should only accept prepared messages.

Benefits: Improves locality of persona design. If we change the persona, we don't touch the router. The router becomes a deep module for handling network operations.

3. Refactor Slash Commands to Strategy Pattern

LLM-Prompt-Injection Sandbox-Evolving Candidate
Strong

Files: backend/services/slash_handler.py

Problem

slash_handler.py contains massive multi-line XML strings (<system_directive>) for every command. It mixes HTTP request handling, formatting prompts, and business logic. It's a shallow module that violates the deletion test: deleting a command requires hunting through a giant if/elif chain.

Solution & Benefits

Extract a CommandStrategy interface. Each command defines its own class with get_system_injection(). The handler just routes to the right strategy.

Benefits: Creates a clean seam for adding new commands. locality is greatly improved: one command = one file/class.

After (Deepened)

Top Recommendation

I strongly recommend tackling Candidate 3: Refactor Slash Commands to Strategy Pattern first. The slash handler is the primary interface for user interaction and is growing rapidly. By creating a deep module with a clear CommandStrategy interface, we establish a robust seam that isolates future commands, improving testability and code navigability significantly.
