1. 当前改动功能详解与架构流程图

彻底废弃浅层过渡脚本 talk_to_fox.py，在应用层构建高leverage（杠杆率）的双向智能体专线。

Inbound Seam

openclaw.py 路由接缝

外部智能体连入本后端的稳定seam（接缝）。对外暴露 POST /api/openclaw/talk 及沙盒文件接口。极简的interface（接口）封装了复杂的implementation（实现）：自动执行上下文组装、流式结果文本聚合以及 os.path.commonpath 沙盒物理路径校验护栏。

Outbound Module

openclaw_client.py 模块

向 WSL 发送指令的外推module（模块）。其 send_to_openclaw() 函数将跨终端命令的错误捕获与 JSON 反序列化集中管理，显著提升了调用的locality（局部性）。

Native Adapter

mcp_server.py 适配器

针对大模型调用的原生adapter（适配器）。提供 talk_to_meiwenfeng 及沙盒工具集，把底层的业务能力直接转化为工具定义，实现了单次接口定义对多调用方的强力leverage（杠杆率）。

现状摩擦 (Problem)： 路径越权防护逻辑 (os.path.commonpath) 分散在 openclaw.py 路由和 agent_tools.py 工具层，存在重复实现与校验覆盖盲区。
深化方案 (Solution)： 下沉提取统一的 SandboxVFS module（模块）作为沙盒唯一访问seam（接缝），实现单一interface（接口）对全项目的安全覆盖。
架构收益 (Wins)
  • ✓ locality: 物理边界防护集中于一处模块
  • ✓ leverage: 一套接口同时支撑 REST 与 MCP
  • ✓ 删除冗余: 消灭多份散落的路径断言代码

候选二：会话同步执行接缝深化 (Conversation Turn Execution Seam)

Worth exploring in-process
涉及文件：backend/routers/openclaw.py · backend/routers/chat.py · backend/services/model_router.py
现状摩擦 (Problem)： 当前 API 路由层在适配非流式问答时，需要在 HTTP 函数内部显式手动遍历生成器 stream_chat()，使路由控制层直接感知大模型底层 SSE 生成实现。
深化方案 (Solution)： 在核心对话引擎中提供内聚的 execute_turn_sync() interface（接口），吸收生成、错误拦截与字符串组装等全套底层implementation（实现）。
架构收益 (Wins)
  • ✓ depth: HTTP 路由层缩减为一行调用
  • ✓ locality: 对话记忆状态变化收敛在核心层
  • ✓ 接缝清晰: 业务流式与异步回执完全解耦
Top Recommendation (首选建议)

优先落地候选一：统一沙盒虚拟文件系统深模块 (Sandbox VFS Deep Module)

按照 AGENTS.md 架构决议与深模块标准，沙盒文件交互（读、写、列出）是连接智能体自动演进与物理文件系统的核心咽喉。将 os.path.commonpath 越权防御与文件 IO 收敛为高leverage（杠杆率）的 SandboxVFS 深模块，可以确保项目全局接口与安全隔离的唯一真实标准 (SSOT)。
