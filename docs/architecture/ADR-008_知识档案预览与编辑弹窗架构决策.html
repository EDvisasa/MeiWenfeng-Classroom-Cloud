知识档案预览与编辑弹窗架构决策

将原来依赖于聊天流内联嵌入的 markdown_doc 卡片展示机制，重构为独立解耦的全局浮层弹窗（PreviewEditModal），并打通底层沙盒防穿透写入锁与 RAGFlow 异步知识库索引同步管线。

🛡️ Sandbox-Evolving (用户测验练习沙盒动态演进) 📚 RAG-Vector-Indexed (知识库卡片向量化索引) 🗺️ State-Decoupled (前端状态与UI拓扑解耦)
1

背景与技术挑战 (Context & Challenges)

聊天流污染与教学文档闭环反馈编辑缺失

挑战一：聊天会话流被内联文档卡片严重污染

旧架构中，用户在右侧资源树点击 `.md` 文件，系统会直接往 `messages` 对话数组中强行塞入一条 `markdown_doc` 消息。当用户频繁查阅多份讲义时，对话窗口被冗长的文档内容淹没，彻底破坏了师生对白的沉浸感与连贯性。

挑战二：只读锁限制与知识同步脱节

现有后端 `materials_manager.py` 仅提供了文件读取能力，缺乏对 `data/materials/` 下文件安全保存修改的回路；同时，在修改教材完好后，若无法及时同步更新至 RAG 向量知识库，将导致 AI 导师所掌握的教学知识与真实文件发生“脑裂”。

2

决策方案与深模块解耦 (Decision & Solution)

纯全局弹窗解耦、防穿透写锁与异步 RAG 索引驱动

2.1 前端全局浮层与会话流绝对解耦 (Pure Global Modal)

废弃在 `ChatPanel` 对话流中渲染 Markdown 文件的旧模式。新增独立全局模态组件 PreviewEditModal，当用户点击右侧文件树或引用链接时，直接在屏幕中央打开弹窗。弹窗内置 **【📖 效果预览 (Preview)】** 与 **【✏️ 源码编辑 (Edit)】** 双向无缝切换视图，让对话流回归纯粹的人机交互。

2.2 开放全量材料写权限与防穿透保护 (Secure Write Lock)

在后端 `MaterialsManager` 中扩充 save_material_content(rel_path, content) 核心方法，向 `Lessons/`、`Sandbox/`、`References/` 及 `LDRs/` 四大目录全面开放 `.md` 写入权限。同时严格绑定 `os.path.abspath` 防目录穿透校验与 `.md` 后缀检查，确保任何恶意路径请求被阻断于安全边界之外。

2.3 后台异步自适应 RAG 向量化索引同步 (Async RAG Indexing)

为保障极致交互响应，当用户点击【保存】时，后端将文本更新落盘后以极速返回 HTTP 200 OK；同时通过异步任务向 `rag_client.sync_knowledge({rel_path: content}, dataset_name="Classroom_Knowledge")` 发送更新请求，保证 AI 导师知识库实时自适应重建，毫无界面延迟。

后果与架构评估 (Consequences & Evaluation)

架构列装后的技术收益与边界

  • ✓ 极简纯粹的对话沉浸感：聊天窗口彻底摆脱大段文档卡片的刷屏干扰，保证了沉浸式的师生交互。
  • ✓ 零延迟的知行合一闭环：用户在沙盒练习或阅读讲义时随时可以修改存盘，并由后台异步管线自动完成 RAG 知识更新，真正做到“即改即同步即教学”。
  • ✓ 绝对安全的文件沙盒锁：严格的 `abspath` 校验保证了即便开放写入权限，系统物理机及父目录也能得到 100% 的隔离保护。
