Adopted (已落地列装) 编号: ADR-013
决策时间：2026-11-13 | 决策方：媚吻锋架构审查团队 / Antigravity

多课题物理沙盒隔离与课时授课闭环决策

彻底重构原全局单例教学目标（ADR-006）与扁平术语表（ADR-003），在 data/materials/courses/ 与底层 SQLite 中引入课题级物理多租户隔离。打通 /set_mission 自动建卷、/lesson 双轨选课授课、术语与 RAG 向量防污染隔离，以及阶段化课时进度编排全链路。

Multi-Course-Isolation (多课题物理隔离) Lesson-Period-Engine (课时进度编排) Anti-Contamination (知识库与术语防污染) Auto-Scaffolding (目标设立自动建卷)
1

背景与技术挑战 (Context & Challenges)

全局单例设计导致的目标割裂、跨学科知识污染与授课无锚点

挑战一：目标设立与课题建卷割裂 (Decoupled Mission)

原架构（ADR-006）中，/set_mission 将学习契约硬编码写入全局单例 user_mission (id=1) 与 Settings/user_mission.md。而档案库的多课程（courses//）仅靠前端弹窗手工新建，两者完全断层，无法自动为新设立的学习目标构建课程专属沙盒与大纲。

挑战二：跨学科知识严重交叉污染 (Knowledge Contamination)

术语抽取（<glossary>）存入单一无分区的数据表中，讲义卡片（<explainer>）与沙盒演练写穿到全局 References/ 与 Sandbox/，RAG 向量检索无课号隔离。当用户学习量子物理或 Navier-Stokes 方程时，经常误召回前端或后端开发的无关切片与歧义术语。

挑战三：授课缺乏课题锚定与课时安排 (No Lesson Periods)

原 /lesson 指令仅针对全局单一的 course_progress 表做顺序推进，既不能按学科选课，也没有“第 1 课时、第 2 课时”等结构化课时编排，无法对不同研究方向分别沉淀学情与 ZPD 动态系数。

挑战四：缺乏闭环的自动化建卷管线

用户设立复杂科研或工程学习目标后，必须脱离对话流手动到档案库创建文件夹并命名。流程摩擦巨大，破坏了陪伴导师引导学习的连贯心流体验。

2

决策方案与深模块解耦 (Decision & Solution)

多租户课题物理隔离、自动建卷、课时化大纲与向量防污染屏障

2.1 数据库多租户扩展与全局活跃指针

新增 courses 实体主表（id, name, status, created_at, last_accessed_at）。在存量表 user_mission、course_progress 与 glossary 中全量动态追加 course_id TEXT DEFAULT 'default'。在系统上下文维护全局活跃课题指针 active_course_id，无缝兼容存量 default 基础课程。

2.2 /set_mission 自动提炼代号与无缝建卷落盘

大模型在强阻断审问终态提案中，根据目标语义自动生成合法规范的英文 ASCII 代号（如 pde_navier_stokes），并在契约卡片中呈报。用户确认签署 <finalize_mission> 时，后端拦截器自动调用 MaterialsManager.create_course(course_id, name) 生成 5 大物理目录，将目标存入 courses/<course_id>/Settings/user_mission.md，并在数据库激活该课程。

2.3 双轨选课与阶段化课时授课闭环 (/lesson)

支持在右侧状态栏与档案库下拉菜单随时切换活跃课题；同时支持无参 /lesson（推进当前活跃课题）与带参 /lesson <course_id>（一键切课并授课）。在 course_progress 中增加 lesson_no 支持课时序列表。授课达标后通过 <system_pass> 自动推进该课题专属课时。

2.4 术语表、沙盒文件与 RAG 向量多层严格防污染隔离

GlossaryHandler 将提取的术语绑定 course_id 并镜像至 Settings/glossary.json；沙盒代码工具（create_file, replace_file_content）动态锚定在 courses/course_id/Sandbox/；RAG 向量库在检索时强制注入 where={"course_id": active_course_id} 过滤条件，彻底杜绝跨学科知识污染。

2.5 四步闭环交互授课流程 (The 4-Stage Interactive Lesson Pipeline)

确立标准化的微课时交互闭环，引导学员从被动听讲转为深度主动攻坚：

阶段一：课题锚定与学情装配 执行 /lesson 锁定活跃 course_id，装载专属 user_mission.md、当前第 N 课时任务与专属 RAG 切片。
阶段二：苏格拉底式启发对齐 导师结合前序课时掌握度，抛出贴近最近发展区 (ZPD) 的启发式问题与 <quiz> 测验卡片，绝不直接给出答案。
阶段三：动态演进沙盒与讲义生成 讲义生成 (<explainer>) 与术语提取 (<glossary>) 精准写入该课程。导师调用工具向 courses/course_id/Sandbox/ 注入挑战代码，学员在真实环境中实操修改。
阶段四：系统关卡放行与课时推进 学员代码调试成功且掌握扎实后，导师触发 <system_pass>。系统将当前课时标记为已完成，自动递增激活下一课时，动态刷新 ZPD 难度与评分。

2.6 “上课生动高效”与“下课生活情趣”的情境化心流隔离机制 (In-Class vs Off-Class Separation)

解决角色扮演陪伴与严肃硬核教学之间的张力，通过状态机与指令前置屏障实现“一主双态、边界分明”：

课堂内 (上课态 · 静心专注 / Socratic Rigor)
  • 状态指令驱动：执行 /lesson 后注入强教学规约，切换为“端庄清雅名师”风范，严禁在解题与编码期间产生暧昧推诿或废话套话。
  • 生动非僵化：导师运用其聪慧、敏锐的性格特质，通过精妙比喻、启发式探问与学术性适度调侃调动学习兴致，实现高信噪比教学。
  • 防漂移硬关卡：必须经受严格的沙盒实操代码校验，未完全攻克前绝不允许通过撒娇或闲聊跳过关卡。
课堂外 (下课态 · 生活情趣 / Everyday Intimacy)
  • 自然转场脱敏：课时完成或输入 /cooldown 后，系统卸载强教学拦截指令，转回温润细腻的日常陪伴节奏。
  • 生活情趣与动态潮汐：好感度潮汐衰减、生理不应期与久别重逢状态在此生效，支持端茶对弈、闲聊日常见闻与情感互动。
  • 认知负荷彻底释放：下课后不强行推销课后作业，给学员留足心智咀嚼空间，确保生活情趣与学术攻坚张弛有度。

后果与架构评估 (Consequences & Evaluation)

架构列装后的技术收益与系统边界

  • ✓ 目标与课程彻底贯通：用户在对话流中设立长期目标时，系统无缝自动建立物理课程卷和标准子目录，消除手工建目录的摩擦。
  • ✓ 多学科知识彻底物理防污染：术语、讲义卡片、实操沙盒代码以及 RAG 向量切片均具备精确的 course_id 边界，不同领域概念绝不串扰。
  • ✓ 课时化与阶段大纲循序渐进：授课体系具备清晰的“第 N 课时”推进模型，与 ZPD 动态难度系数深度耦合，学习进度一目了然。
  • ✓ 100% 存量向下兼容：通过将旧有全局材料映射为 default 课程，存量单测与已有用户数据毫无破坏。
  • ✓ 课堂硬核攻坚与下课温存陪伴和谐统一：通过心流状态机（静心专注名师风范 vs 生活日常温润情趣）物理隔离教学认知负荷与情感陪伴，既保障了课堂内攻坚的高压、严谨与高信噪比，又保留了课后温存陪伴的趣味与温度。
