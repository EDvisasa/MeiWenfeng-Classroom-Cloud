上下文管线深模块与尾部夹层 O(1) 组装架构决策

由候选报告 context_manager_architecture_report 升格列装。践行 Matt Pocock “深模块 (Deep Modules)” 与 DDD “通用语言 (Ubiquitous Language)” 哲学，收纳解决 Bug #6、Bug #7、Bug #9、Bug #12 (ISSUE-11)。彻底解耦 ContextManager 与 prompts.py，设立角色白名单拦截 UI 专属卡片，消除 === [DYNAMIC_BOUNDARY] ===` 字符串切割，并将尾部人设注入从 O(N) 倒序扫描重构为 O(1) 极速追加。

🏷️ LLM-Prompt-Injection (人设与系统提示词注入拦截) ✨ Roleplay-Immersion (酒馆式角色扮演沉浸) ⚡ O(1)-Complexity-Engine (O(1) 极速上下文追加)
1

演进背景与技术挑战 (Context & Challenges)

浅层管线偶合、倒序遍历开销与领域术语歧义

⚠️ 浅层管线与 UI 角色泄露

原有 ContextManager 是典型的浅模块，依赖脆弱的字符串切割 (=== [DYNAMIC_BOUNDARY] ===) 区分提示词边界。此外，管线未对前端专用交互角色 (system_info) 进行清洗拦截，导致其直接泄露发往大模型 API 引发报错（Bug #6 / Bug #9）。

❌ 尾部夹层 O(N) 倒序扫描

在为对话追加动态尾部人设与 RAG 切片时，旧代码采用 O(N) 倒序遍历整个消息历史寻找最后的 AI 回波，甚至暴力将已存回波篡改为 user 角色。这不仅消耗不必要的 CPU 循环，更割裂了历史上下文问答语境（Bug #12 / ISSUE-11）。

🌀 “系统提示词”语意重载

前后端长期将“顶部静态规则”和“发往 API 的全量报文”笼统称为“系统提示词 (System Prompt)”。严重语意重载导致开发者和用户在交互预览与排错时发生认知解耦，无法清晰感知尾部夹层与历史轮次的界限。

2

决策方案与深模块解耦 (Decision & Solution)

三步洗净管线、O(1) 极速追加与 DDD 通用语言硬化

核心决策一：三步洗净管线与 One-Shot 模板解耦

在 assemble_messages 中确立严谨的三步处理管线：首先通过角色白名单 ({'system', 'user', 'assistant', 'tool'}) 拦截剥离所有非 LLM 原生的 UI 交互消息；随后将原来硬编码在管线中的 20 行 One-Shot 示教模板彻底解耦下沉至 prompts.py，实现业务模板与核心管线的关注点分离。

核心决策二：O(1) 尾部夹层追加与待机轮次容器

彻底废除 _inject_dynamic_tail 中的 O(N) 倒序循环。改为通过 messages[-1] 进行 O(1) 物理末尾判定：若末尾已经是 user 提问，则直接在其内容后方换行追加动态尾部夹层；若末尾是 assistant（AI 回合刚完结），则在末尾独立构造一个专属的 待机轮次容器 (Standby Turn Container) 承载夹层，确保零历史割裂与极速执行。

核心决策三：全库通用语言硬化 (Ubiquitous Language)

严格遵照 /ubiquitous-language 技能规范，消除“系统提示词”语意重载，硬化为以下四大规范概念并在全库文档与前端 UI（ChatPanel.jsx）全量落地：

规范术语 (Canonical Term) 核心定义 (Tight Definition) 避免使用的歧义词 (Aliases to avoid)
静态系统预设
(Static Persona Prompt)		 仅指处于会话物理最顶部的 role: system 报文，承载角色性格、教学守则与常量设定。 系统提示词、全局预设、System Prompt
动态尾部夹层
(Dynamic Tail Injection)		 在每次发包前由 ContextManager 动态追加至物理末端的上下文感知块，整合当前时间戳、RAG 检索切片与底层防错指针。 尾部提示词、小尾巴、最后的话、系统尾缀
实时组装报文视窗
(Assembled Context Payload)		 经过洗净、单发示教与尾部夹层组装后，最终全量发往大模型 API 交互的完整会话报文序列展现（前端弹窗透视）。 完整系统提示词、系统预设预览
待机轮次容器
(Standby Turn Container)		 在 AI 回合完结后、用户下一轮提问前，为承载尾部夹层而在物理末端独立构造的临时 user 角色占位卡片。 空问答、占位符、假消息

后果与长期收益 (Consequences & Evaluation)

局部性极佳、高杠杆率与 100% 回归测试保障

⚡ 极致的算法效率与局部性 (Locality & Speed)

尾部夹层追加时间复杂度从 O(N) 彻底降至 O(1)。在长达数百轮的长上下文课堂对话中，CPU 无需再倒序循环和发生额外内存拷贝。所有消息洗净与注入逻辑 100% 收敛在 ContextManager.assemble_messages 内部，局部性极佳。

🛡️ 零回滚风险与高杠杆率 (Leverage & Safety)

一个 ContextBundle 接口服务于全系统所有模型路由。本次重构及 DDD 通用语言硬化已通过 test_context_manager.py 中 13 个联合回归测试套件（含 Bug #6, #7, #8, #9, #12）100% 验证绿灯。前后端界面与术语保持全量统一，用户互动清晰直观。
