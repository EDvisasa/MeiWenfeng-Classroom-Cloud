记忆原子单元不分块与长教材标题继承切片架构决策

彻底解耦“通用长篇教材切片”与“高密度压缩记忆管理”，将 Memory_Knowledge 记忆集合重构为【单日记事件原子单元（Atomic Capsule）】整体入库，永久废除 400 字符腰斩切割；对 Classroom_Knowledge 长教材切片升级为【语义整句截断 + Markdown 标题前缀继承】，彻底消除时间戳丢失与碎句断字现象。

🧠 Atomic-Memory-Unit (记忆原子胶囊整篇入库) 🏷️ Header-Inheritance (长教材切片元数据继承) ✂️ Sentence-Boundary (句号/换行自然边界切分) 🛡️ Zero-DB-Pollution (零数据变动代码层无感升级)
1

背景与技术挑战 (Context & Challenges)

机械定长切片在业务异构知识库中的设计错配

挑战一：400 字符硬切割导致记忆文档被拦腰切断

在 chroma_client.py 初始实现中，为了适应本地模型 MiniLM-L12-v2 的 128 Token 窗口，全局硬编码了 chunk_size = 400。然而，记忆衰减生成的 Level 1~4 日记全文约 450~600 字，恰好超过 400 字阈值，导致整篇日记被粗暴横切为 Chunk 0 和 Chunk 1，不仅破坏了词语结构（如将“水镜画卷”截断成 Chunk 0 的“水镜画”和 Chunk 1 的“卷”），更使得第二切片从半句话或残字开头。

挑战二：第二切片丢失【记录时间】头，沦为无头公案

当大模型在检索记忆时，若根据语义相似度召回了 Chunk 1（如记录中后部的详细事件或学情洞察），因头部仅包含在 Chunk 0 中，Chunk 1 完全不具备 【记录时间：...】 与时间跨度标签，导致注入到大模型动态提示词中的记忆失去时序锚点，甚至诱发角色认知混乱。

2

决策方案与深模块解耦 (Decision & Solution)

知识分类分流治理：记忆原子胶囊化 + 教材继承分块化

2.1 压缩记忆（Memory_Knowledge）—— 原子单元整篇存储，绝不切片

压缩记忆（Level 1~4 日记）本身就是 LLM 高度提炼的结构化事实胶囊，属于单一不可分割的原子事件。在 sync_knowledge 中识别 dataset_name="Memory_Knowledge" 时，将单块大小阈值提升至 1000 字符以上（完整包裹整篇日记），禁止对其切片。每一条入库记忆均包含完整的【记录时间】、【时间跨度】、【详细纪要】与【学情洞察】，一网打尽。

2.2 长篇教材（Classroom_Knowledge）—— 语义整句截断与标题继承

对于数千上万字的技术教材，保留分块机制，但重构切片规则：
1）自然句号边界对齐：切片只允许在句号、感叹号、问号或双换行（。！？\n）处换行，严禁在词组中硬截；
2）元数据头继承（Header Inheritance）：每个切片生成时，自动提取文档顶级标题与所属二级章节，格式化为 【文档：xxx / 章节：yyy】 预先追加在 Chunk 开头，确保大模型无论抽中哪一碎片都能精准建立全局上下文感知。

2.3 零数据库破坏与完全向后兼容 (Zero-DB Pollution)

此改动仅作用于应用层向量切分与 RAG 同步回路，完全无需清空或改动底层 SQLite classroom.db 中的任何一行用户数据，亦不影响现存 chat_messages 的历史完整性。

后果与架构评估 (Consequences & Evaluation)

系统稳态收益与工程守则

  • ✓ 100% 杜绝时间戳脱落：记忆日记作为整体存储后，召回的任何切片永远天然携带 【记录时间：YYYY-MM-DD HH:MM:SS】，彻底解决时序识别困难。
  • ✓ 彻底消除文字与词组碎裂：永远不会再发生将“水镜画卷”劈为“画”与“卷”、或将“3.5与3.8”劈为“8、27B”的严重断词故障。
  • ✓ 知识库语境高可解释性：教材切片自动附加章节标题，极大提升了小参数量模型（如 35B-A3B）在长文本复杂提问下的泛化理解能力。
  • ✓ 零数据库负担：完全基于现有向量集合与接口扩展，无需实施破坏性的数据库全量迁移或洗库。
