- [x] **补全缺失的后端 API**：实现了 `POST /api/chat/models/update`（保存 API 配置）和 `GET /api/chat/models/available`（获取可用子模型列表）两个此前遗漏的端点
- [x] **子模型输入框改造**：将下拉 `<select>` 改为带 `<datalist>` 联想提示的 `<input>` 输入框，支持手动输入无法枚举模型列表的公益站/第三方 API 模型名
- [x] **RAG 多后端切换系统**：引入 `rag_factory.py` 工厂模块，支持三档知识库后端一键切换：
  - 🚀 **ChromaDB（默认）**：本地向量库，零外部依赖，轻量高效
  - ☁️ **RAGFlow**：保留原有完整接入，需 Docker 服务在线
  - 🔗 **外部 API**：预留 Dify、FastGPT 等第三方 RAG 服务接口
- [x] **记忆系统语义升级**：ChromaDB 模式下，每次对话结束后自动将对话向量化存入本地 `conversation_memory` Collection；每次发消息时同时做知识库检索 + 对话记忆语义检索，替代原有低效的 RAGFlow 关键词搜索
- [x] **前端知识库配置 UI**：在右上角 ⚡ API 配置面板底部新增 📚 知识库后端 三档切换按钮，RAGFlow/外部 API 模式下展开对应的地址和密钥输入框

## ✅ 最新完成内容 (2026-06-13 会话)
- [x] **修复 ChromaDB 并发初始化冲突**：为本地 ChromaDB 客户端增加 `threading.Lock` 线程锁，彻底解决了因为 `sentence-transformers` 首次拉取模型耗时较长引发的知识库错误初始化与多线程并发竞态问题（500 Internal Server Error）。
- [x] **补全知识库后端解耦逻辑**：清理并修复了 `/api/chat/files/sync` (单文件同步) 与 `memory_decay.py` (记忆总结算法) 中遗漏的 `ragflow_client` 硬编码调用 Bug，确保全量功能均严格使用 `get_rag_client()` 动态分发。
- [x] **内置数据库监控大屏**：新增 `DatabaseViewer.jsx` 前端组件和配套的只读路由接口 `db_viewer.py`，支持在浏览器端实时审查底层 SQLite 结构和所有系统记录数据，打通“黑盒开发”的壁垒。
- [x] **记忆归档算法重构**：优化大模型记忆归档提示词算法，引入严格的**“时间跨度四段式”**（时间、核心词、一句话总结、详细描述）规范，并通过脚本提取时间戳直插 Prompt 解决模型自发幻觉引发的时间线错乱丢失问题。
- [x] **老旧数据清洗合并**：开发 `migrate_memory.py` 清洗脚本，全自动完成旧版冗余或混乱 `Level 1`、`Level 2` 数据的四段式重排版处理，并将规范化后的新数据无缝同步入 ChromaDB 的 `Memory_Knowledge` 集合。
- [x] **对话流底层 RAG 指示灯**：重构了 `rag_client.retrieve` 使其直接返还切片数组用于精准分类计数，在每次响应生成**前**利用 SSE 回传独立角色 `system_info` 数据包，以居中悬浮框形式清晰告知用户本次检索调用了多少份“讲义片段”与“长期记忆”。
